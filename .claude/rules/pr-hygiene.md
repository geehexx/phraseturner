# PR Hygiene

## Base branch

phraseturner repo (`geehexx/phraseturner`): feature branches → `main` (no `development` branch; single-repo single-track).

```bash
# Correct
gh pr create --head feat/my-feature --title "feat: ..."
```

## Before opening any PR

1. `git status --short` — confirm no uncommitted changes.
2. `git log --oneline @{u}..HEAD` — confirm you're pushing what you think.
3. `git diff --stat main...HEAD` — sanity-check diff size.
4. Run `uv run pytest -q --no-header` locally; must pass.
5. Run `uv run ruff check src/ tests/` and `uv run mypy src/`; must pass.

## PR title and body

- Conventional commits: `feat(cv): ...`, `fix(scrapers): ...`, `chore: ...`, `docs: ...`.
- Under 70 chars. Body carries detail.
- Include `## Summary` (1-3 bullets) and `## Test plan` (bulleted checklist).
- **No AI attribution** (no "Co-Authored-By: Claude", no "Generated by AI").
- **No internal tooling paths** (`.kiro/`, `memory://`, agent names as implementation detail).

## No force-push to shared branches

- `main` — never force-push, ever.
- Feature branches (`feat/*`, `fix/*`) — `--force-with-lease` only, never `--force`.

## Merging

- User approves merges. Never merge PRs automatically.
- Squash-merge for single-purpose branches.
- CodeRabbit (if wired) + CI green before requesting review.
